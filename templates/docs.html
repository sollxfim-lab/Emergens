Emergens API Documentation

The Emergens API provides programmatic access to the 35 web security testing modules. Run scans, retrieve results, and manage your account from any application. This guide covers authentication, endpoint usage, and best practices.

Authorized Use Only. All scanning activities must comply with applicable laws and the terms of service. You must have explicit permission to test any target.

Authentication

All API requests require a valid API key. Pass the key in the Authorization header using the Bearer scheme.

Authorization: Bearer emg_sk_live_69b215b08f66480295691864a0c9bf57bfed6903

To obtain an API key, log in to your dashboard and navigate to Settings → API Keys. Keys are scoped to your account and can be revoked at any time.

Keep your key secure. Never expose it in client-side code or public repositories. Treat it like a password.

Base URL

All endpoints are relative to the following base URL:

http://node1.lunes.host:2381

Use HTTPS when available in production environments. The API accepts JSON payloads and returns JSON responses.

Scan Lifecycle

Scanning is asynchronous. A typical workflow consists of three steps:

  1. Start a scan — POST to /api/scan/start with target and options. Receive a job_id.
  2. Poll status — GET /api/scan/{job_id}/status until status is "completed" or "failed".
  3. Retrieve results — GET /api/scan/{job_id}/results to fetch the full report.

Scans may take from a few seconds to several minutes depending on target complexity and selected modules.

Start Scan

Initiates a new vulnerability scan.

Request

POST /api/scan/start
Content-Type: application/json
Authorization: Bearer YOUR_API_KEY

{
  "target": "example.com",
  "mode": "basic",
  "tools": ["xss", "sql_injection", "nmap"],
  "options": {
    "max_depth": 3,
    "timeout": 60,
    "user_agent": "EmergensScanner/1.0"
  }
}

Required parameters: target. Optional: mode (basic, full, custom), tools (array of tool IDs), options (advanced settings).

Response

{
  "job_id": "abc123def456",
  "status": "queued",
  "message": "Scan started successfully"
}

Scan Status

Check the current state of a scan job.

GET /api/scan/abc123def456/status
Authorization: Bearer YOUR_API_KEY

Response

{
  "job_id": "abc123def456",
  "status": "running",
  "progress": 42,
  "current_module": "xss",
  "started_at": "2026-08-25T10:30:00Z"
}

Possible status values: queued, running, completed, failed.

Retrieve the detailed report after a scan completes.

List Tools

Retrieve all available security testing modules and their IDs.

GET /api/tools
Authorization: Bearer YOUR_API_KEY

The response includes an array of tools with properties: id, name, category, description.

Error Codes

The API returns standard HTTP status codes. Detailed error information is provided in the response body.

Status Code Description
400bad_requestInvalid parameters or malformed JSON.
401unauthorizedMissing or invalid API key.
403forbiddenInsufficient permissions or plan limit exceeded.
404not_foundJob or resource not found.
429rate_limitedToo many requests. Check Retry-After header.
500internal_errorUnexpected server error.
Rate limited? Wait for the Retry-After interval before making another request.

Webhooks

Configure webhooks to receive real-time notifications when a scan completes.

  1. Go to Dashboard → Settings → Webhooks.
  2. Provide your endpoint URL.
  3. Select events (scan.completed, scan.failed).
  4. Verify the signature using the shared secret.

Example payload:

{
  "event": "scan.completed",
  "job_id": "abc123def456",
  "target": "example.com",
  "summary": { "critical": 1, "high": 2 },
  "timestamp": "2026-08-25T10:31:27Z"
}

SDKs & Libraries

Official SDKs are available for the following languages:

  • Python — pip install emergens-sdk
  • JavaScript — npm install emergens-sdk
  • PHP — composer require emergens/sdk
  • Ruby — gem install emergens-sdk

Refer to the SDK documentation for usage examples and helper methods.
